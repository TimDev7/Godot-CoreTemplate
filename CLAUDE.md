# CLAUDE.md — Godot Core Template

Самый абстрактный уровень в цепочке шаблонов: `Godot-CoreTemplate` → `Level-based Template` (шаблон игр с уровнями) → конкретная игра (например `block-fit`). Каждый следующий уровень — форк-вперёд (`git clone`, не submodule/пакет), живой связи между репозиториями нет. Изменения сюда попадают, когда что-то, найденное в конкретной игре, оказывается универсальным для ЛЮБОЙ будущей игры студии — жанро-агностичным, не привязанным к конкретной механике.

## Архитектура проекта

- **`template/`** — переиспользуемая инфраструктура между ВСЕМИ играми: `Core`-автозагрузка (EventBus, SaveManager, SoundManager), UI-кит (`juicy_*`), SDK-фасад (`template/sdk/sdk.gd`), `Haptics`. Жанро-агностично, меняется редко, рассчитано на долгую жизнь за пределами этого репозитория.
- **`game/`** — минимальный каркас конкретной игры (`BaseGame`, `GameData`), который каждая игра расширяет своими сценами и механиками. То, что специфично для ОДНОЙ игры (паззл-механика, уровни и т.п.), сюда не попадает — это уровень `Level-based Template` или самой игры.
- **Автозагрузки** (`project.godot` → `[autoload]`), порядок важен: `Core` → `Bridge` → `GPX` → `Game` → `CG`. Причина: код в `_ready()` одной автозагрузки не может полагаться на то, что другая уже готова, если та идёт позже в списке (`Game._ready()` синхронно читает `Bridge.platform`/`GPX.gpx`/`CG.sdk` — при неверном порядке будет `Invalid access ... on a base object of type 'Nil'`).
- **`template/sdk/sdk.gd` (`SDK`)** — единственная точка входа в рекламу/аналитику/платформенные сигналы. Игровой код звонит `SDK.*`, никогда не трогает `Bridge.*`/`GPX.*`/`CG.*` напрямую. Защита от повторного вызова рекламы, от "залипшего" состояния Bridge (`_bridge_ad_stuck_in_progress()`) и корректный pause/mute-lifecycle уже встроены в сам `SDK`.
- Три раздельных портальных SDK за одной игрой: **Playgama Bridge** (`addons/playgama_bridge` — Y8 и др.), **GamePix-плагин** (`addons/gpx-godot-plugin` — только GamePix) и **hand-written CrazyGames-обёртка** (`addons/crazygames_sdk` — официального Godot-пакета не существует, см. её же README.md). Это три разных экспорт-пресета (`export_presets.cfg`: `Web`/`GamePix`/`CrazyGames`) с разными HTML-шеллами — один билд не может обслуживать больше одного портала одновременно.
- `Core.toggle_pause(turn_on, source)` — раздельные источники паузы (`_pause_sources`-словарь), не один общий bool. Причина: меню паузы игрока и `SDK`'s ad-flow оба могут захотеть паузу одновременно — плоский bool позволил бы одному источнику снять паузу другого.
- Web-специфика: `NOTIFICATION_APPLICATION_FOCUS_OUT/_IN` НЕ срабатывает на смену вкладки браузера (godotengine/godot#87014) — `core.gd` слушает `document.visibilitychange` напрямую через JS и транслирует как `event_bus.app_hidden_changed`; `user://` на Web асинхронно/с задержкой пишется в IndexedDB и может не долететь до закрытия вкладки (godotengine/godot#39643, #56640) — `save_manager.gd` на Web использует синхронный `window.localStorage` вместо `user://`.

## Жёсткие правила

- **Ноды/сцены — на пользователе в редакторе. Скрипты/логика/тесты — на Claude.** `.tscn`, `export_presets.cfg` и структура аудио-шин (`.tres` с `AudioBusLayout`) **никогда** не редактируются вручную текстом, пока открыт редактор — он держит свою копию в памяти и молча затирает ручные правки при следующем сохранении. Настройки экспорта/автозагрузки/плагинов/аудио-шин — только через сам редактор.
- После каждого прогона headless-редактора (`--headless --editor ... --quit`) проверять `git diff --stat -- '*.tscn'` — такой прогон может непреднамеренно пересохранить открытые сцены.
- **Тесты — только для `template/`** (Core, SDK-фасад, переиспользуемые менеджеры и UI-кит). Никогда — для кода конкретной игры (`game/`-каркас, только когда он специализируется в игре), даже при фиксе реального бага: проверять запуском/playtest, не тестом. Причина: `template/` живёт годами и используется в каждой новой игре, баг там дорог; игровой код живёт неделю-две и дешевле проверить глазами, чем поддерживать тесты.
- Перед интеграцией любого стороннего SDK/плагина или лимита портала — проверять первоисточник (код, официальную документацию), не пересказ по памяти или из гайдов.
- Отвечать пользователю на русском.
- **Коммитить на контрольных точках** (рабочая фича готова, баг подтверждённо починен, конец сессии) — предлагать коммит самому, не дожидаться просьбы. Сам коммит — только с явного разрешения пользователя (как и всегда для git-операций).
- В репозитории настроен remote (GitHub `TimDev7/Godot-CoreTemplate`) — пуш только по явной просьбе, не автоматически при каждом коммите.

## GDScript-грабли (проверено на практике)

- Лямбды захватывают локальные переменные **по значению** и пересоздают снимок на каждый вызов — мутация внутри не переживает даже повторный вызов той же лямбды и не видна снаружи. Для общего изменяемого состояния — одноэлементный `Array` (ссылочный тип), не голый `var`.
- `match` с паттерном через автозагрузку (`SomeAutoload.ENUM.VALUE`) молча никогда не срабатывает — паттерн должен быть реальной константой. Использовать `if/elif`.
- Присваивание нетипизированного array-литерала в строго типизированный `Array[T]` через слабо типизированную (`Node`) переменную падает в рантайме — сначала собрать типизированный локальный `Array[T]`.
- Новый `class_name` не виден, пока редактор его не зарегистрирует — нужен один headless-прогон редактора (`--headless --editor --quit`, дать ему **полностью** завершиться, не обрывать по таймауту/`--quit-after N` — незавершённый скан может оставить `.godot/`-кэш (UID/global-class) в частично обновлённом состоянии, из-за чего автозагрузки резолвятся в `Nil`, а `class_name`-скрипты — в пустой `GDScript`-заглушку).
- Автозагрузки готовятся в порядке, в котором перечислены в `project.godot` — код в `_ready()` одной автозагрузки не может полагаться на то, что уже готова другая, если та идёт позже в списке.
- `SceneTree.create_timer()` в headless GUT-раннере (`gut_cmdln.gd`) может реально сработать спустя секунды реального времени независимо от заданной длительности — не полагаться на точный тайминг в тестах, которые ждут срабатывания таймера; давать щедрый запас (секунды, не десятые доли) в `wait_seconds()`.
